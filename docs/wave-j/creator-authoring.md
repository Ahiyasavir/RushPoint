Scope: game creation + the transforms that copy/publish/translate/import games.
Read-only audit of `functions/src/games/index.ts`, `functions/src/runs/index.ts`
(launchRun / startInstantPlay), `packages/shared/src/{validation,importSheet,gating,

## Clean bills (verified robust — no change needed)

- **requiredTaskCount > task count** — clamped at launch: `Math.max(1, Math.min(stage.requiredTaskCount, stage.tasks.length))` (`runs/index.ts:179-181`). `validateUnlockGraph` also emits a (non-blocking) warning. No strand. *Note:* the warning IS silently dropped by `updateGame` (games/index.ts:153 collects `.errors` only), but the launch clamp makes it harmless.
- **Empty game / 0-task stage at launch** — rejected in `launchRun` (`runs/index.ts:202-216`). (The *non-launch* consumers are the gap — see J1/J2/J3.)
- **geofenceRadiusMeters: 0 / negative** — defended: `evaluateTrigger` (`geo.ts:88`) and `evaluatePresence` (`geo.ts:128`) both fall back to the mode default radius when the radius isn't finite-and-positive. Never strands a player at the correct spot.
- **Task at coordinates {0,0}** — treated as the null-island sentinel and NOT proximity-gated in `completeTask` (`runs/index.ts:2899-2904`); so the `blank`/default-template `{lat:0,lng:0}` task stays winnable.
- **Unwinnable answer-key tasks** (quiz/numeric/smart_station/sequence with no key) — caught at BOTH `updateGame` (games/index.ts:182) and `launchRun` (runs/index.ts:218) via `taskCompletabilityError`. `isTaskCompletable` (taskCompletability.ts:19-39) covers every answer-bearing type incl. the ordering-quiz variant.
- **Unlock graph** — self-reference, cross-stage/unknown ids, and cycles are save-blocking in `validateUnlockGraph` (`gating.ts:102-183`, wired at `updateGame:153`); a cycle-free graph always leaves a prerequisite-free source, so the stage stays routable.
- **duplicateGame** — deep spread copy, strips the webhook secret (games/index.ts:331), resets `visibility`/`allowInstantPlay`/`playCount`, fresh top-level id. Keeps the source's internal stage/task ids, which is correct (ids need only be unique *within* a game, and routing references them within the copied game — no dangling cross-game reference).
- **translateGame structure preservation** — `applyTranslations` deep-clones via `JSON.parse(JSON.stringify)` and has a `__proto__`/`constructor`/`prototype` prototype-pollution guard (`translateFields.ts:56`); only display text (title/description/hint) is collected — `numericAnswer`, `steps[].answer`, coordinates, and types are never touched; `answers[]` translation keeps the original as an accepted alias (games/index.ts:560-564). No answer-key corruption.
- **CSV export** (`RunConsolePage.tsx:1340-1364`) — escapes leading `=+-@` (formula injection) and quotes `",\n`; and it only emits task ids + numeric analytics, never creator titles, so the import-title → CSV injection vector never materializes here.
- **Quick-start templates** (`templates.ts`) — all niche + starter templates produce winnable games (quizzes carry `answers`, the sequence carries `steps`, photos `autoApprove`); the `blank` template's single empty `{0,0}` task is winnable via the null-island sentinel (above).

Not a corruption bug per se, but a spreadsheet with `points:"1e999"` → `Infinity` → `Number.isFinite` false → falls back to default 50; worth a quick fuzz row to confirm no `NaN`/`Infinity` slips into `pointValue`.
