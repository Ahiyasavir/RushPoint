## B. Security: found, NOT fixed (decide / schedule)

### B0. TOP PRIORITY — attempt-limit / station-code brute force via parallel submission (**High**, confirmed in two callables)
`submitTaskAnswer` (`functions/src/runs/index.ts:~6911`) reads `attempts` from a **non-transactional** `teamRef.get()` and checks `attemptLimitReached(attempts, …)` *before* grading; the increment happens later in a separate transaction. N concurrent submissions all read `attempts = 0`, all pass the gate, all get graded — so a 1-attempt quiz is brute-forced with one burst (up to the 30/min rate limit). `verifyStationCode` (`functions/src/index.ts:~1922`) has the identical pattern and, with no `attemptLimit` set, has no wrong-code cooldown at all. **Fix (needs a proper OpenSpec change + full `e2e`/`simulate`/adversarial suite, RED first — do NOT hand-roll against the scoring hot path):** reserve the attempt transactionally before grading — read+increment `taskAttempts[taskId]` and enforce the cap in ONE transaction, after the replay dedup, so a legitimate network retry still does not consume an attempt. Apply the same to station codes and consider extending `resolveWrongAnswerLevel`'s cooldown to them.

## C. Held up well (tested by reading the code)

Secrets: nothing real in 1,152 commits of a PUBLIC repo; `android.keystore`, `api.env` and the APKs are ignored and were never committed. Firestore rules are deny-by-default and run/team/score state is server-only. Storage of uploads: content type from a fixed table, unknown ⇒ download, `nosniff`, traversal and root-escape checks. Staff PIN login: per-caller AND run-wide lockout (anonymous-account minting does not help). The CMS GitHub sign-in: CSRF state cookie compared in constant time, token sent only to allow-listed origins. The chat webhook URL is re-validated on read, not just on write. `/ingest-url` re-validates every redirect hop and refuses non-default ports.
