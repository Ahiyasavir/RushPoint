## Why

The creator's Builder concentrates a non-linear, creative workflow into a linear
3-step wizard, and crams the entire task editor into a `max-w-md` modal on a
desktop screen that has 1400px+ of unused horizontal space. Three concrete pains:

1. **Cognitive overload** — the task type (the most creatively significant choice)
   is buried last, inside an "Advanced" accordion; location config, scoring, and
   registration all compete in one scroll.
2. **Wasted real estate** — the modal ignores the desktop canvas; surveying a
   stage means opening/closing tiny 132×96 chips one at a time.
3. **No flow** — there is no spatial relationship between the stage list and the
   task being edited; the modal is cognitive teleportation.

## What — target architecture

A persistent **3-pane shell**, always in Build mode (nothing resets on step
change):

```
Header:  ← Games › <title*>  [Saved]   Build | Preview | Analytics | Settings   [Launch]
┌────────────┬───────────────────────────────┬─────────────────────────────┐
│ Stage Rail │  Task Canvas (virtualized)     │  Context Panel (slide-in)   │
│ 166px      │  flex:1                        │  280px, transform animated  │
│ pacing bar │  full-width type-sprint cards  │  3-step wizard / quiz / etc │
└────────────┴───────────────────────────────┴─────────────────────────────┘
```

- **Header** — tab strip replaces the wizard steps; `Settings` (mode, scoring,
  registration) and `Preview` (route map) become full tabs; `Analytics` is a
  reserved slot for `run-analytics-heatmap`. Inline `contenteditable` title.
- **Stage Rail** — stage cards with a difficulty **pacing bar** (one column per
  task, height = difficulty, colour = type family). Drag to reorder. Footer hosts
  `import-game-spreadsheet`.
- **Task Canvas** — full-width cards with a colour-coded left border (type family)
  + a scannable preview line, so a creator reads pacing/diversity/balance in a
  2-second scroll ("visual type-sprinting"). Virtualized for 100+ task games.
- **Context Panel** — slides in (CSS `transform`, GPU-composited) only when a task
  is selected or created; slides away on Done / `Esc`. Hosts the 3-step task
  wizard (Location → Details → Interaction), Inspiration-Mode templates, and rich
  micro-tooltips.

## Dynamic Quiz input schema (IMPLEMENTED)

The newline-split choices/answers textareas are replaced by a dynamic list of
isolated choice rows (per-row text input + delete + "correct" checkbox + Add
choice). **The persisted schema is unchanged** — still `Task.choices: string[]`
(rendered buttons) and `Task.answers: string[]` (accepted correct values, matched
trimmed + case-insensitive by the participant runtime).

Mapping (pure, `apps/creator-web/src/lib/quizFields.ts`):

| Editor action | Model effect |
|---|---|
| `choicesFromTask` | rows from `choices`; row `correct` ⇔ text ∈ `answers` (norm) |
| legacy typed-answer (answers, no choices) | each answer seeds a correct row (no data loss) |
| `choicesToTask` | `choices` = non-blank row texts; `answers` = correct row texts |
| add / remove / setText / toggleCorrect | immutable row-list transforms |

Backward compatibility is locked by a round-trip test:
`choicesFromTask(choicesToTask(rows))` preserves text + correctness.

## Inspiration Mode + micro-learning

- **One-click samples** (`lib/taskTemplates.ts`, `TASK_SAMPLES` + `applySample`):
  per-type illustrative data so creators learn by editing. `applySample` preserves
  draft identity (id, coordinates) and merges `smart` config rather than replacing.
- **Rich micro-tooltips** (`RichTooltip`): asset-light inline SVG illustrations on
  hover for difficulty (routing-priority ring), geofence radius, hint penalty,
  max-concurrent, est-minutes. Staged.
